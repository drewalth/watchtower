# Local One-Command Production Mode — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a contributor clone the repo and run `make prod` to bring up the entire stack in production mode (gunicorn + pre-built React bundle via WhiteNoise, `DEBUG=0`, migrated + seeded DB, demo admin superuser, background scheduler) in a single terminal tab.

**Architecture:** A self-contained `docker-compose.prod.yml` (run under its own project name `watchtower-prod`) orchestrates `db` → one-shot `init` (migrate + seed + createsuperuser) → `web` (gunicorn) + `scheduler` (viewsheds once, then hourly ingest). A multi-stage `Dockerfile.prod` builds the React bundle with Node, then copies it into a GeoDjango Python runtime and `collectstatic`s at build time. Dev (`docker-compose.yml`, `Dockerfile`, host Vite) is untouched except for one rebuild to pick up WhiteNoise.

**Tech Stack:** Django 5.2 + GeoDjango, gunicorn, WhiteNoise (`CompressedStaticFilesStorage`), django-vite 3.1, Vite/React, Docker Compose, uv, Make.

**Spec:** `docs/superpowers/specs/2026-06-15-local-production-mode-design.md`

**Conventions for this plan:**
- These are **infrastructure** files, so most tasks replace "write a failing unit test" with a **concrete verification command + expected output**. The existing `pytest` suite is the regression guard, run after the settings change and at integration.
- Docker image builds take minutes; that's expected. The heavy builds are concentrated in Task 4 and Task 9.
- All host commands run from the repo root `/Users/andrewalthage/dev/watchtower`.

- [ ] **Step 2: Add STATIC_ROOT and STORAGES**

Find (currently lines ~92–94):
```python
STATIC_URL = "static/"
# Vite writes its built bundle + manifest here; also where collectstatic looks.
STATICFILES_DIRS = [BASE_DIR / "static"]
```
Replace with:
```python
STATIC_URL = "static/"
# collectstatic target — what WhiteNoise serves in production (DEBUG=0).
# Must be distinct from STATICFILES_DIRS below.
STATIC_ROOT = BASE_DIR / "staticfiles"
# Vite writes its built bundle + manifest here; also where collectstatic looks.
STATICFILES_DIRS = [BASE_DIR / "static"]

# Django 5.2 STORAGES dict (do NOT also set the legacy STATICFILES_STORAGE).
# Use WhiteNoise's COMPRESSED (non-manifest) backend: Vite already
# content-hashes filenames, and the Manifest variant's reference-rewriting
# crashes collectstatic on Vite's source-map references.
STORAGES = {
    "default": {"BACKEND": "django.core.files.storage.FileSystemStorage"},
    "staticfiles": {"BACKEND": "whitenoise.storage.CompressedStaticFilesStorage"},
}
```

### Task 4: Add Dockerfile.prod (multi-stage)

Stage 1 builds the React bundle with Node; stage 2 is the GeoDjango runtime that copies the bundle in, installs runtime deps, and `collectstatic`s at build time.

**Files:**
- Create: `Dockerfile.prod`

- [ ] **Step 1: Create the file**

`Dockerfile.prod`:
```dockerfile
# Multi-stage production image. Stage 1 builds the React bundle with Node so the
# final image never ships Node. Stage 2 is the GeoDjango runtime (GDAL/GEOS/PROJ)
# that copies the built assets in and runs gunicorn. Dev keeps using ./Dockerfile.

# ---- Stage 1: build the Vite/React bundle ----
FROM node:24-slim AS assets
WORKDIR /app
# Lockfile first for layer caching.
COPY package.json package-lock.json ./
RUN npm ci
COPY vite.config.ts tsconfig.json components.json ./
COPY assets/ ./assets/
# vite.config sets outDir=./static (emptyOutDir:false), manifest:true
#   -> static/<hashed bundle> + static/.vite/manifest.json
RUN npm run build

# ---- Stage 2: GeoDjango runtime ----
FROM python:3.12-slim AS runtime
ENV PYTHONUNBUFFERED=1 \
    PYTHONDONTWRITEBYTECODE=1 \
    UV_PROJECT_ENVIRONMENT=/opt/venv \
    UV_LINK_MODE=copy \
    PATH="/opt/venv/bin:$PATH" \
    DJANGO_SETTINGS_MODULE=config.settings \
    DJANGO_DEBUG=0

# GDAL/GEOS/PROJ for GeoDjango; gdal-bin is REQUIRED at runtime because
# towers/viewshed.py shells out to gdalbuildvrt/gdalwarp/gdal_viewshed.
RUN apt-get update && apt-get install -y --no-install-recommends \
        binutils \
        libproj-dev \
        gdal-bin \
        libgdal-dev \
    && rm -rf /var/lib/apt/lists/*

COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /bin/

WORKDIR /app
# Runtime deps only (no pytest/ruff). gunicorn + whitenoise must be in the lock.
COPY pyproject.toml uv.lock ./
RUN uv sync --frozen --no-dev

COPY . .
# Built bundle + manifest from stage 1 overwrite the (gitignored) source static/.
COPY --from=assets /app/static/ ./static/

# Collect into STATIC_ROOT at build time (immutable image, fail-fast).
RUN python manage.py collectstatic --noinput

EXPOSE 8000
# Default CMD for `docker run`; compose overrides --workers via env.
CMD ["gunicorn", "config.wsgi:application", \
     "--bind", "0.0.0.0:8000", "--workers", "3", \
     "--timeout", "120", "--access-logfile", "-", "--error-logfile", "-"]
```

### Task 5: Add docker-compose.prod.yml

Self-contained prod stack. Run under project name `watchtower-prod` (Task 6's Makefile passes `-p`). Not an override of `docker-compose.yml`.

**Files:**
- Create: `docker-compose.prod.yml`

- [ ] **Step 1: Create the file**

`docker-compose.prod.yml`:
```yaml
# Self-contained PRODUCTION-MODE stack (local). Run via `make prod`, which uses
# project name `watchtower-prod` so it gets an isolated DB volume and never
# collides with the dev stack. NOT a `-f` override of docker-compose.yml — an
# override can't drop the dev bind-mount, which would shadow the baked bundle.

x-prod-env: &prod-env
  POSTGRES_DB: ${POSTGRES_DB:-watchtower}
  POSTGRES_USER: ${POSTGRES_USER:-watchtower}
  POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-watchtower}
  POSTGRES_HOST: db
  POSTGRES_PORT: 5432
  DJANGO_SECRET_KEY: ${DJANGO_SECRET_KEY:-dev-insecure-key-change-me}
  DJANGO_DEBUG: 0
  FIRMS_MAP_KEY: ${FIRMS_MAP_KEY:-}

x-app: &app
  build:
    context: .
    dockerfile: Dockerfile.prod
  image: watchtower-prod:latest

services:
  db:
    image: postgis/postgis:16-3.4
    environment:
      POSTGRES_DB: ${POSTGRES_DB:-watchtower}
      POSTGRES_USER: ${POSTGRES_USER:-watchtower}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-watchtower}
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER:-watchtower} -d ${POSTGRES_DB:-watchtower}"]
      interval: 5s
      timeout: 5s
      retries: 5

  # One-shot bootstrap: schema, seed data, demo admin. Exits 0; web/scheduler
  # wait on it via service_completed_successfully (so there is no seed/viewshed race).
  init:
    <<: *app
    command: >
      sh -c 'python manage.py migrate --noinput &&
             python manage.py seed_towers &&
             (python manage.py createsuperuser --noinput || true)'
    environment:
      <<: *prod-env
      # Demo superuser (insecure on purpose — single-user demo). createsuperuser
      # --noinput reads these; `|| true` makes re-runs idempotent.
      DJANGO_SUPERUSER_USERNAME: ${DJANGO_SUPERUSER_USERNAME:-admin}
      DJANGO_SUPERUSER_PASSWORD: ${DJANGO_SUPERUSER_PASSWORD:-admin}
      DJANGO_SUPERUSER_EMAIL: ${DJANGO_SUPERUSER_EMAIL:-admin@example.com}
    depends_on:
      db:
        condition: service_healthy
    restart: "no"

  web:
    <<: *app
    command: >
      gunicorn config.wsgi:application --bind 0.0.0.0:8000
      --workers ${GUNICORN_WORKERS:-3} --timeout 120
      --access-logfile - --error-logfile -
    environment:
      <<: *prod-env
    ports:
      - "8000:8000"
    depends_on:
      db:
        condition: service_healthy
      init:
        condition: service_completed_successfully
    restart: unless-stopped

  scheduler:
    <<: *app
    command: >
      sh -c 'python manage.py compute_viewsheds --only-missing || true;
             while true; do
               python manage.py run_ingest_cycle || true;
               sleep 3600;
             done'
    environment:
      <<: *prod-env
    depends_on:
      db:
        condition: service_healthy
      init:
        condition: service_completed_successfully
    restart: unless-stopped

volumes:
  pgdata:
```

### Task 6: Add the Makefile

The discoverable command hub. **CRITICAL: Makefile recipe lines MUST be indented with a literal TAB, not spaces** — spaces produce `*** missing separator`.

**Files:**
- Create: `Makefile`

- [ ] **Step 1: Create the file (recipe lines tab-indented)**

`Makefile`:
```make
.DEFAULT_GOAL := help
COMPOSE      := docker compose
PROD         := docker compose -p watchtower-prod -f docker-compose.prod.yml

.PHONY: help setup prod prod-down prod-logs prod-rebuild superuser \
        dev dev-down seed migrate viewsheds ingest test lint typecheck build

help:  ## Show this help
	@grep -E '^[a-zA-Z_-]+:.*?## .*$$' $(MAKEFILE_LIST) \
	  | awk 'BEGIN{FS=":.*?## "}{printf "  \033[36m%-14s\033[0m %s\n", $$1, $$2}'

setup:  ## First-time: create .env from .env.example if missing
	@test -f .env || (cp .env.example .env && echo "Created .env")

## ---- Production mode (local) ----
prod: setup  ## Build + run the full production stack at :8000 (one tab; Ctrl-C stops)
	$(PROD) up --build
prod-down:  ## Stop and remove the production stack
	$(PROD) down
prod-logs:  ## Follow production logs
	$(PROD) logs -f
prod-rebuild:  ## Rebuild prod images from scratch
	$(PROD) build --no-cache
superuser:  ## Create the demo admin superuser in the running prod stack
	$(PROD) exec web python manage.py createsuperuser

## ---- Development ----
dev: setup  ## Start dev backend (Docker) + Vite (host) — open :8000
	$(COMPOSE) up -d --build
	npm install && npm run dev
dev-down:  ## Stop the dev backend
	$(COMPOSE) down

## ---- Data / db (operate on the dev stack) ----
seed:  ## Seed the 27 lookout towers
	$(COMPOSE) exec web python manage.py seed_towers
migrate:  ## Apply migrations
	$(COMPOSE) exec web python manage.py migrate
viewsheds:  ## Compute viewsheds for towers missing one
	$(COMPOSE) exec web python manage.py compute_viewsheds --only-missing
ingest:  ## Run one ingest cycle (fires/weather/risk/predict)
	$(COMPOSE) exec web python manage.py run_ingest_cycle

## ---- Quality ----
test:  ## Run the pytest suite (in the container)
	$(COMPOSE) exec web pytest
lint:  ## Ruff lint
	$(COMPOSE) exec web ruff check .
typecheck:  ## TypeScript typecheck (host)
	npm run typecheck
build:  ## Build the frontend bundle (host)
	npm run build
```
